# 终期总结报告范例提取与验收指南

## 适用范围

本指南基于“企业实习总结报告-范例.docx”提取的目录和版式规律，用于终期报告。它不替代学校之后下发的正式终期模板或评分表；二者冲突时，以正式文件为准。

## 范例结构

前置部分依次为中文摘要、中文关键词、英文摘要、英文关键词、目录。正文为九章：实习概况、复杂工程问题归纳与实施方案可行性研究、针对复杂工程问题的方案设计与实现、知识技能学习情况、工程协作交流情况、工程计划管控与执行情况、职业素养与工程伦理的学习与培养、对软件工程实践以及软件工程领域发展的认识、结束语；末尾为参考文献和致谢。

## 版式契约

- 使用用户提供的终期模板或范例 `.docx` 作为生成脚本的 `--template` 参数，保留其封面、目录、页面尺寸、边距、目录字段、页码和正文样式。
- 范例为 A4 纵向页面，左右边距 1.25 英寸，上下边距 1 英寸；不要在 Markdown 中重新声明这些格式，交由 Word 模板继承。
- 正文采用模板的 `Normal` 样式；一级、二级、三级标题必须使用真实 `Heading 1` 至 `Heading 3` 样式，以供目录字段识别。
- 先对范例执行版式提取，记录页面尺寸、边距、页眉/页脚距离、字体、中英文混排、缩进、行距、标题层级、图题/表题、目录样式及各分节的默认页/奇偶页/首页页眉。不得凭经验套用通用 Word 样式。
- 范例的一级标题居中、加粗；二、三级标题为左对齐层级标题。实际字体、字号与段前段后距由模板控制，脚本仅补齐报告约定的中英文字体与字号。
- 一级标题必须从新页开始。终期范例使用按章分节的页眉，生成器必须为每个一级标题的默认页、奇偶页和首页页眉写入本章标题；页脚页码继承模板。任何页面出现上章、`ABSTRACT` 或空白页眉均为失败。
- 图、表、代码和测试用例只在帮助说明工程证据时使用。每个图表须有连续编号、题注及正文引用；表格列宽应按内容配置，代码片段必须简短并脱敏。

## 内容连续性与证据矩阵

- 终期报告以中期报告为底稿：中期中已完成的项目、职责、难点、解决过程和引用不得消失；后期成果作为同一实习过程的自然延续补入。
- 先建立“项目 -> 本人职责 -> 可核验证据 -> 对应章节 -> 图表”矩阵。摘要、1.2、1.3、3.3、9.1、9.2 和致谢必须覆盖完整项目序列，不能将最后补入项目单独设为价值主线。
- 每个关键项目至少选择一种最能解释工程关系的图：架构图、业务流程图、状态图、数据流图、时序图或测试流程图。第5章至少包含一张真实的跨角色协作泳道图。图必须源自已核验事实，并在正文以“如图X-Y所示”解释其作用。
- 图表不能替代正文，也不能用装饰性图形凑数量。无法公开的界面、代码或数据使用脱敏流程图、结构图或测试表替代。

## 目录、文献与致谢

- 目录必须在最终分页完成后更新并复核。优先使用 Word/WPS 更新域；若自动域无法得到稳定缓存，按最终 PDF 的实际页码生成静态目录。严禁交付页码全为 1、全部为 0、提示“打开后更新”或未核验的目录。
- 参考文献先继承中期报告中与终期内容仍有关联的条目，再为新增项目补充真实、可查且在正文实际引用的资料。数量应与项目与技术范围相称，不能只保留后期新增项目的少量文献。
- 致谢需覆盖实习单位提供的实践机会、指导老师在需求理解/方案/质量/复盘上的指导、各项目的产品/前后端/测试等协作同事，以及学校或学院支持。不得将致谢缩减为对某一项目或单一 Eval 建议的感谢。

## 终期交付检查

1. 使用 `template-final.md` 规划九章内容，并建立初期、中期、终期任务闭环表。
2. 确认摘要与第1、2、3、9章中的角色、模块、问题和成果表述一致。
3. 确认第2、3章形成完整证据链：任务/约束、方案、实现、测试或验收结果。
4. 确认第4至8章都有对应工作事实，且不把团队成果、推测数据或通用感想写成个人事实。
5. 检查所有图片、截图、日志、接口、代码和数据是否需要脱敏；没有授权时只描述机制，不附原始材料。
6. 生成 docx 后更新目录字段，并执行渲染检查：目录页码与最终 PDF 一致；页眉与章节一致；所有图表和表格无截断；代码不溢出；字体无替换；参考文献和致谢完整。环境没有 LibreOffice 时，至少使用 Word/WPS 或其他可用渲染器完成逐页检查；无法完成时必须明确为未通过视觉验收，不能声称排版合格。
